redistributing or externally deploying this fork. External deployment includes
making the work available for use by someone other than yourself, including
through a network, as defined in section 5 of the license.

For every distributed binary, provide the corresponding complete source code
under OSL-3.0. Include this fork's changes and the files needed to modify and
build it, including the Gradle configuration, wrapper, Stonecutter targets, and
jei-api project. A sources JAR alone is not a complete repository snapshot.
Identify the source revision corresponding to each binary. An accessible source
repository or an accompanying complete source archive can provide that source;
an upstream repository without the fork's changes cannot.

Retain LICENSE, ATTRIBUTION.md, and all third-party notices. Include a copy of
the license with the delivery and prominently identify this as a modified fork.
Do not use the original authors' names or trademarks to imply endorsement.

Make a reasonable effort to obtain recipients' express assent to OSL-3.0 under
section 9. For example, present the license and require an explicit acceptance
before a download or pack delivery. Use an equivalent explicit acceptance step
for direct transfers. A statement that merely using the mod counts as express
assent does not establish that the recipient actually expressed assent.

The distributor must arrange source access and the acceptance step before
delivery. Building a JAR locally does not publish its source or obtain a
recipient's assent. Keep the source available for the distributed work and do
not replace it with a different revision under the same release identifier.
